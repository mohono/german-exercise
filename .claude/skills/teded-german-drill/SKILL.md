# آلمانی با TED-Ed (برای مبتدی)

کاربر فارسی‌زبان است و از آلمانی **هیچ نمی‌داند**. الفبای لاتین را می‌شناسد، ولی هیچ قاعدهٔ آلمانی را نه. این پروژه دو کار می‌کند:

1. **تمرین ویدیویی (یادآوری فعال):** هر ویدیوی کانال https://www.youtube.com/@TEDEdGerman یک فایل HTML می‌شود، **دقیقاً مثل تمرین‌های انگلیسی کاربر ولی برای آلمانی**: متن به‌صورت جمله‌های **فارسی** نمایش داده می‌شود. کاربر روی یک جمله می‌زند، اگر خواست آلمانی‌اش را در کادر می‌نویسد (دکمه‌های ä ö ü ß هست)، Enter می‌زند و **آلمانی + دکمهٔ 🔊 صدای واقعیِ جمله + کارتِ تک‌تک کلمه‌ها (دکمهٔ 🔊 صدای واقعی کلمه، معنی، توضیح دستوری) + نکته‌ها** باز می‌شود؛ Enter دوباره یعنی جملهٔ بعدی.
2. **توضیح دلخواه:** کاربر جمله یا متنی آلمانی می‌فرستد و همان ساختار را در چت می‌گیرد (بخش ۹).

جهتِ تمرین همیشه **فارسی ← آلمانی** است (کاربر صریحاً همین را خواسته؛ جهت را عوض نکن). چون کاربر مبتدی است، پنل پاسخ **پُر** است: صدای واقعی همهٔ کلمه‌ها و توضیح دستوری هم می‌آید، نه فقط جملهٔ آلمانی. نوشتن در کادر اختیاری است.

تلفظ دیگر با نویسهٔ فارسیِ تقریبی نوشته نمی‌شود؛ `drill.py build` با Piper TTS (صدای آلمانیِ محلی، بدون نیاز به اینترنت یا کلید API) برای هر کلمهٔ یکتا و هر جملهٔ کامل صدا می‌سازد و آن را به‌صورت base64 داخل خودِ فایل HTML جا می‌دهد، پس هر صفحه هنوز یک فایل مستقل است.

## ۱. جریان «ادامه»

وقتی کاربر می‌گوید «ادامه» / «continue»:

1. `python3 scripts/fetch.py next` — تازه‌ترین ویدیوی کانال که در `video-ledger.md` نیست. اگر ویدیوی تازه‌ای نیامده باشد، همان ویدیوی بعدیِ پردازش‌نشده در آرشیو است. خروجی را در یک خط به کاربر بگو: شمارهٔ ویدیو، عنوان، تاریخ، مدت.
2. `python3 scripts/fetch.py get <videoId>` — متن آلمانی در `transcripts/<videoId>.txt` (اگر فایل هست، بازنویسی نمی‌شود چون ممکن است غلط‌هایش دستی اصلاح شده باشد).
3. متن را **کامل** بخوان و غلط‌ها را طبق بخش ۲ درست کن.
4. منبع را طبق بخش‌های ۳ تا ۷ در `sources/<NNN>-<Slug>.txt` بنویس (`NNN` شمارهٔ ترتیبی سه‌رقمی، `Slug` از عنوان آلمانی به لاتین ساده).
5. `python3 scripts/drill.py build sources/<NNN>-<Slug>.txt` سپس `python3 scripts/drill.py check sources/<NNN>-<Slug>.txt`. تا `OK:` نیامده کار تمام نیست.
6. ردیف تازه در `video-ledger.md` (بخش ۸)، سپس commit و push.

فقط **یک ویدیو در هر نشست**.

## ۲. اصلاح متن (فقط غلط‌های آشکار)

زیرنویس‌های این کانال ترجمه‌ای است و ممکن است غلط داشته باشد (نام‌های خاص انگلیسی‌نویس‌شده، کلمهٔ چسبیده، حرف اضافه). برای کسی که آلمانی را از صفر یاد می‌گیرد، آلمانیِ غلط بدتر از تغییر کوچک در متن است. پس:

- **درست کن:** غلط تایپی و کلمهٔ خراب (`administrativden denkenden` → `administrativ denkenden`)، نام خاصی که آشکارا غلط نوشته شده (`Jinges Kahn` → `Dschingis Khan`)، نقطهٔ اضافی وسط جمله، غلط دستوری کاملاً آشکار و کوچک (`über den … Empire` → `über dem`).
- **دست نزن:** سبک، ترتیب کلمه‌ها، جمله‌های ثقیل ولی درست، انتخاب واژه.
- اصلاح را در خود `transcripts/<videoId>.txt` انجام بده (با اسکریپتی که تعداد هر جایگزینی را `assert` می‌کند) و **هر اصلاح را در یادداشت‌های ledger بنویس** (قبل → بعد).
- اگر غلط دستوری مشکوک بود ولی مطمئن نبودی، متن را نگه دار و در `*` نکتهٔ همان واحد بنویس.
- متن را هرگز خلاصه، جابه‌جا یا بازنویسی نکن.

## ۳. شکستن به واحد

- هر واحد یک تکه از متن است؛ واحدها پشت‌سرهم با یک فاصله باید **دقیقاً** برابر `transcripts/<videoId>.txt` شوند (`drill.py check` این را می‌سنجد).
- اندازه: معمولاً ۴ تا ۱۳ کلمه؛ جمله‌های بلند را سرِ ویرگول یا حرف ربط (`und`، `dass`، `um … zu`) ببُر. مبتدی با پنل بلندِ ۲۰ کلمه‌ای خسته می‌شود.
- خط `+para` در یک واحد یعنی پاراگراف تازه از همین واحد شروع می‌شود؛ سرِ تغییر موضوع بگذار (تقریباً هر ۵ تا ۹ واحد).
- نقطهٔ بعد از عددِ ترتیبی (`7.`، `19.`) پایان جمله نیست؛ آن را از `Jahrhundert` جدا نکن.

## ۴. قالب فایل منبع

فایل `sources/<NNN>-<Slug>.txt`، بلوک‌ها با یک خط خالی جدا می‌شوند. بلوک اول سرفصل است:

```
video: <videoId>
fa-title: <عنوان فارسی، بدون " < &>

de: <یک واحد آلمانی، دقیقاً مثل متن>
fa: <ترجمهٔ طبیعی فارسیِ همین واحد>
+para                                   (اختیاری)
- <کلمه> | <معنی> | <توضیح دستوری، اختیاری>
- …                                     (یک خط برای هر کلمه، به همان ترتیب)
* <نکته به فارسی؛ آلمانی داخل <de>…</de>>   (اختیاری، تکرارپذیر)
```

قواعد سخت (`drill.py check` می‌سنجد):

- **هر کلمهٔ واحد یک خط `-` دارد**، به همان ترتیب، با همان املا (علامت‌های نگارشی دو سر حذف می‌شوند: `Christus,` → `Christus`؛ `7.` → `7`؛ `Assur-uballit` یک کلمه است). فقط قطعه‌های بدون حرف و رقم (مثل `–`) خط ندارند.
- معنی فارسی است.
- برچسب‌های `<de>…</de>` باید جفت باشند.
- **تلفظ را دیگر ننویس.** `drill.py build` خودش برای هر کلمهٔ یکتا و هر جملهٔ کامل صدای واقعی آلمانی می‌سازد (بخش ۵)، پس ستون تلفظ از فرمت منبع کاملاً حذف شده.

## ۵. تلفظ = صدای واقعی (Piper TTS)

دیگر تلفظ با نویسهٔ فارسی نوشته نمی‌شود. `drill.py build` به‌ازای هر کلمهٔ یکتا (بدون حساسیت به بزرگی/کوچکی حرف) و هر جملهٔ کامل (`de`) یک‌بار صدا می‌سازد، نتیجه را در `.cache/tts/` (کش محلی، در git نیست) با هش متن ذخیره می‌کند، و به‌صورت base64 داخل خودِ فایل HTML جا می‌دهد — صفحه هنوز یک فایل مستقل است، فقط حجمش چند مگابایت بیشتر می‌شود.

**راه‌اندازی یک‌باره (قبل از اولین build):**

```bash
pip3 install --user piper-tts
mkdir -p ~/.cache/piper-voices
curl -sL -o ~/.cache/piper-voices/de_DE-thorsten-medium.onnx \
  "https://huggingface.co/rhasspy/piper-voices/resolve/main/de/de_DE/thorsten/medium/de_DE-thorsten-medium.onnx"
curl -sL -o ~/.cache/piper-voices/de_DE-thorsten-medium.onnx.json \
  "https://huggingface.co/rhasspy/piper-voices/resolve/main/de/de_DE/thorsten/medium/de_DE-thorsten-medium.onnx.json"
```

بعد از این، `drill.py build` خودکار کار می‌کند؛ نه کلید API لازم است نه اینترنت (فقط بار اول برای دانلود مدل). `ffmpeg` هم باید نصب باشد (صدای Piper را به Opus کم‌حجم تبدیل می‌کند).

- صدای هر کلمه جدا از صدای جمله ساخته می‌شود (نه چسباندن کلمه‌ها به هم)، چون آهنگ و تکیهٔ جمله با کلمهٔ تنها فرق دارد.
- کش با هش متن کار می‌کند، پس اگر فقط معنی یا نکته‌ای را ویرایش کنی، صداهای قبلی دوباره ساخته نمی‌شوند و build سریع می‌ماند.
- صدای Piper گاهی روی نام‌های خاص یا کلمه‌های نامتعارف طبیعی نیست؛ این یک محدودیتِ شناخته‌شده است، نه چیزی که باید در متن منبع درستش کنی.

## ۶. ستون‌های کارت هر کلمه

- **معنی (`m`):** معنی‌ای که **در همین جمله** درست است، نه فهرستِ لغت‌نامه؛ کوتاه.
- **توضیح دستوری (`g`)، همیشه برای:**
  - اسم: جنس و حرف تعریف و جمع (`مؤنث: <de>die Stadt</de>، جمع: <de>die Städte</de>`)، و حالت (Nominativ/Akkusativ/Dativ/Genitiv) وقتی از ظاهر پیدا نیست.
  - فعل: زمان و شکلِ مصدر (`گذشتهٔ ساده از <de>erobern</de>`)، جداشدنی بودن، بی‌قاعده بودن (`gehen → ging → gegangen`)، وجهی بودن.
  - صفت: علتِ پایانش (`-en چون datif`).
  - حرف اضافه: حالتی که می‌خواهد (`همیشه datif`).
  - حرف ربط: اگر فعل را آخر می‌برد.
  - ادغام‌ها: `im = in + dem`.
- برای کلمه‌های بسیار ساده (`und`، `die` در تکرار چندم) می‌شود `g` را کوتاه یا خالی گذاشت، ولی همیشه اولین بار در ویدیو توضیح بده. حرف تعریف را با «(حرف تعریف)» و جنس و حالتش بنویس.
- **هیچ کلمه‌ای را رد نکن**، حتی نام‌های خاص و عددها (صدا و معنی می‌گیرند).

## ۷. ترجمه و نکته‌ها

- **جملهٔ فارسی (`fa`) همان چیزی است که کاربر می‌بیند و باید از روی آن آلمانی را به یاد بیاورد.** پس: (۱) روان و طبیعی باشد ولی **شفاف**: هر عنصرِ معنایی آلمانی (زمان، حالت نفی، حرف اضافه، قید) از فارسی قابل‌بازیابی باشد؛ (۲) **به سمت کلمهٔ هدف هل بدهد** (برای `erstreckte sich` بگو «امتداد داشت»، نه «بود» تا کلمهٔ درست به ذهن بیاید)؛ (۳) **هیچ توضیح یا پرانتز یا نکته‌ای که پاسخ را لو بدهد در `fa` نیاید**؛ توضیح‌ها به `*` نکته‌ها و ستون `g` می‌روند؛ (۴) اگر آلمانی چیزی دارد که فارسی نیاز ندارد (مثلاً `es gab`)، در نکته بگو.
- **نکته‌ها (`*`)** فقط برای نقطه‌هایی که واقعاً چیزی یاد می‌دهند: جایگاه فعل (V2، فعل آخرِ جملهٔ فرعی، جداشدنی‌ها)، حالت‌ها (Akkusativ/Dativ/Genitiv)، مجهول، وجهی‌ها، کلمهٔ مرکب، ادغام‌ها، الگوهای ثابت (`um … zu`، `sich interessieren für`). هر نکته یک یا دو جمله؛ نکته‌ای را که در واحد قبلی دقیق گفته‌ای تکرار نکن، فقط اشاره کن. مبتدی با نکتهٔ زیاد و درهم غرق می‌شود.
- در ویدیوهای اول، اصول را بیشتر توضیح بده؛ هرچه ویدیوهای بعدی می‌آیند و الگوها تکرار می‌شوند، توضیح‌ها کوتاه‌تر شوند و به توضیح قبلی اشاره کنند («مثل بالا: فعل جملهٔ فرعی آخر می‌رود»).
- عددها: آلمانی‌ها سال‌ها مثل `1300` را «سیزده‌صد» می‌خوانند، ولی Piper معمولاً رقم به رقم یا هزارگانی می‌خواند، نه به سبک سال؛ این محدودیت TTS است، نه چیزی که در متن منبع درستش کنی — اگر خیلی مهم بود، در نکته اشاره کن که خوانش صحیح چیست.

## ۸. ledger و commit

`video-ledger.md`: جدولی با ستون‌های شمارهٔ ویدیو، `videoId` (**داخل بک‌تیک؛ فقط شناسه‌ها**)، عنوان آلمانی، انتشار، تاریخ پردازش، تعداد واحد، تعداد ردیف کلمه، به‌علاوهٔ بخش یادداشت‌ها با فهرست اصلاح‌های متن. اگر ledger و فایل‌ها ناسازگار بودند، فایل‌ها درست‌اند.

```bash
git add sources/<NNN>-<Slug>.txt texts/<NNN>-<Slug>.html transcripts/<videoId>.txt video-ledger.md \
 && git commit -m "ویدیوی <N> — <عنوان آلمانی> (<واحد> واحد، <کلمه> کلمه)" && git push
```

پیش از commit: `git status` را نگاه کن و مطمئن شو `.env` در فهرست **نیست** و رشتهٔ کلید API در diff نیست.

## ۹. توضیح جملهٔ دلخواه

وقتی کاربر متن یا جملهٔ آلمانی می‌فرستد (نه از ویدیو): همان ساختار را در چت بده. برای هر جمله:

1. جمله،
2. ترجمهٔ فارسی،
3. فهرست کلمه‌به‌کلمه (کلمه — معنی — نکتهٔ دستوری)،
4. نکته‌های دستوری.

چت نمی‌تواند صدا پخش کند، پس اینجا تلفظ نوشته نمی‌شود. اگر کاربر صدای واقعی همین جمله را خواست، یک صفحهٔ HTML مستقل و کوچک با همان پایپ‌لاین Piper TTS (بخش ۵) بساز، بدون افزودن آن به `sources/`، `texts/` یا ledger — چون از ویدیو نیست.

اگر کاربر بعداً خودش جملهٔ آلمانی نوشت، اشتباه‌هایش را نرم و روشن بگو و شکل درست را با دلیل بده. فایل HTML یا commit در این حالت لازم نیست، مگر خواسته شود.

## ۱۰. نکته‌های سخت

- HTML را **فقط** با `drill.py build` از `sources/*.txt` بساز، هرگز دستی ویرایشش نکن. قالب `assets/drill-template.html` تنها منبعِ موتور است؛ بهبود موتور اول در قالب انجام می‌شود، بعد همهٔ صفحه‌ها با `build` بازسازی می‌شوند (`check` صفحهٔ کهنه را رد می‌کند).
- کلید API (`SUPADATA_API_KEY`) فقط در `.env` است (git-ignore). آن را در هیچ فایل، commit یا پیامی ننویس.
- متن آلمانی را عوض، خلاصه یا مرتب نکن (جز اصلاح‌های بخش ۲).
- ویدیوهای بلند (بیش از حدود ۲۰ دقیقه) در supadata با job ناهمزمان می‌آیند؛ `fetch.py` خودش صبر می‌کند.
